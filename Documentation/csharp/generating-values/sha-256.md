---
title: SHA-256 digests
description: Derive deterministic fingerprints and high-entropy token verifiers from UTF-8 text.
---

Use `GenerateValue.Sha256(string value)` for a deterministic fingerprint or a stored verifier of a
server-generated bearer token with at least 128 bits of entropy. It adds no randomness or entropy.
It is not encryption, an anonymizer, or a password hashing function.

## The text contract

The result is the SHA-256 digest specified by FIPS 180-4, rendered as exactly 64 lowercase hexadecimal characters.
The input is well-formed UTF-16 text encoded as UTF-8 without BOM insertion, Unicode normalization or case folding.
A literal leading U+FEFF is preserved and hashed, not stripped. Empty text is valid. `null` throws
`ArgumentNullException`; an unpaired UTF-16 surrogate throws `InvalidSha256Input`, without including the input in its message.

```csharp
using Cratis.Concepts;

var digest = GenerateValue.Sha256("abc");
// ba7816bf8f01cfea414140de5dae2223b00361a396177a9cb410ff61f20015ad
```

Hash the text as supplied, not a decoded representation. If a token was generated as base64url text, hash that
text, not the bytes obtained by decoding it. Callers canonicalize first if their domain requires it: `e\u0301`
and `\u00e9` have different digests, as do `jane@example.com` and `Jane@example.com`.

## A fingerprint concept

A digest depends on an existing value. Use `From(value)`, not `IGeneratable` or `New()`:

```csharp
using Cratis.Concepts;

public record ContentFingerprint(string Value) : ConceptAs<string>(Value)
{
    public static ContentFingerprint From(string value) => new(GenerateValue.Sha256(value));
}
```

Equal input yields an equal digest. A fingerprint is not proof of authenticity: anyone who knows the input can
recompute it. Use a keyed construction such as HMAC when you need a keyed authenticator, not this unkeyed hash.

## A bearer token verifier

For server-generated tokens with at least 128 bits of entropy, return the raw token once and persist only its digest:

```csharp
using Cratis.Concepts;

public record TokenDigest(string Value) : ConceptAs<string>(Value)
{
    public static TokenDigest From(string token) => new(GenerateValue.Sha256(token));
}
```

At issuance, generate `var token = GenerateValue.Bytes(32);` and persist `TokenDigest.From(token)`.
Return `token` once to the caller. Never log it, include it in events, or keep it as recoverable plaintext.
On presentation, derive a digest from the supplied token text and compare it with the stored digest.

For a direct comparison, use `CryptographicOperations.FixedTimeEquals` over equal-length digest bytes, not string equality:

```csharp
using System.Security.Cryptography;

// storedDigest and presentedDigest are TokenDigest values containing validated 64-character hex digests.
var matches = CryptographicOperations.FixedTimeEquals(
    Convert.FromHexString(storedDigest.Value),
    Convert.FromHexString(presentedDigest.Value));
```

Lookup by digest index is not constant-time. That pattern is acceptable only for server-generated tokens with
at least 128 bits of entropy, where an attacker cannot feasibly enumerate the token space. It is not a way to
verify guessable secrets. Expire and rotate tokens; the digest is not an authorization decision.
See [Secrets and tokens](secrets-and-tokens.md) for generation, audit markings and storage rules.

## Security boundaries

- **Not for passwords or other low-entropy input.** SHA-256 is fast and unsalted. Use a password hashing function
  with a salt and a slow algorithm for passwords, PINs and short codes.
- **Not encryption.** A digest is not recoverable key material. Store TOTP secrets and keys in protected,
  recoverable storage when their original value is needed later.
- **Not anonymization.** A digest of personal data is still personal data: common emails, phone numbers and other
  guessable values can be enumerated. Equality also links repeated values.
- **Not secret erasure.** The implementation clears its temporary UTF-8 buffer in a `finally` block with
  `CryptographicOperations.ZeroMemory`, before returning any rented buffer to the pool. Input and output strings
  cannot be erased; callers must still keep them out of logs and permanent event payloads.

## Test it exactly

No seed or clock is needed. Assert the exact expected digest for fixed text, including empty text and Unicode
cases. The shared `sha-256.json` fixture uses FIPS 180-2 Appendix B anchors and additional vectors cross-computed
with Python `hashlib` and Node `crypto`. Invalid inputs use UTF-16 code-unit arrays, not lone surrogates in JSON strings.
